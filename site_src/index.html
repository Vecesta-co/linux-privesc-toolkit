The Privilege Escalation Problem

Understanding how subtle configuration oversights create high-impact privilege boundary transitions.

⚠️ The Security Gap

Privilege escalation occurs when an unprivileged account or process gains access beyond its intended operational authority. Misconfigured SUID bits, permissive cron scripts, unconstrained sudo rules, or legacy kernel releases frequently bridge this gap on production Linux servers.

🔍 Auditing vs Exploitation

Traditional penetration tools often attempt active exploitation, which risks service disruption or production instability. This toolkit enforces an explicit boundary: it captures file metadata and configuration text, applies transparent deterministic rules, and provides defensive remediation guidance without ever firing an exploit.

What It Checks

Comprehensive inspection of the eight primary local privilege escalation attack surfaces.

⚙️ SUID / SGID

Locates SUID/SGID binaries, cross-references against standard system allowlists, and highlights GTFOBins execution contexts.

📂 Permissions

Scans world-writable files, sensitive configuration files (/etc/passwd, /etc/shadow), and vulnerable home directories.

⚡ Sudo Policies

Inspects non-interactive sudo listing and sudoers drops-ins for NOPASSWD grants and broad command privileges.

⏰ Cron Automation

Parses system cron tables, detecting user-writable root job targets, wildcard expansion traps, and relative binary paths.

🔧 systemd Services

Inspects unit service files and drop-ins for root-privileged services executing writable scripts or insecure PATH entries.

🏷️ File Capabilities

Queries extended file attributes via getcap to identify privilege-altering capabilities (e.g., cap_setuid).

🐧 Kernel Advisories

Evaluates running kernel versions against known local privilege escalation CVEs (Dirty Pipe, Dirty COW) with distribution backport warnings.

👤 System Context

Records host identity, user groups, effective privilege, and detects container or WSL environments to isolate mount traversals.

Architecture & Data Flow

Clean architectural separation: read-only collectors, pure parsers, analysis rules, and structured formatters.

Component Architecture

The safe command runner represents the only process execution boundary. Discovered binaries are never executed.

Scan Execution Flow

Sequential execution pipeline from system discovery to rule analysis and multi-format report export.

Disposable Lab & 3-Act Demo

A reversible validation lifecycle designed to evaluate detection efficacy safely in a disposable environment.

Act 1: Clean Baseline

Performs an initial audit of the target environment to record standard system configuration and identify any baseline findings before lab creation.

Act 2: Planted Weaknesses

Creates 7 isolated, reversible misconfigurations (tracked in a strict manifest) and runs audits as root and as an unprivileged account.

Act 3: Teardown & Compare

Purges all manifest-tracked lab files and user accounts, reruns the scan, and computes a differential comparison proving clean remediation.

Safety Model & Ethical Bounds

Engineered defensively to guarantee system integrity during auditing operations.

🛡️ Strict Command Allowlist

privesc/runner.py enforces an unbypassable allowlist of read-only commands (find, uname, id, getcap, crontab, sudo -n -l, systemctl cat). Dangerous flags like -exec or -delete are rejected immediately.

🚫 Zero Payloads & Zero Exploitation

The codebase contains zero shellcode, exploit payloads, or breakout commands. Findings provide defensive remediation steps and references.

🔒 Runtime Hash Integrity Proof

The automated demo captures cryptographic SHA-256 hashes of critical security files (/etc/passwd, /etc/group, /etc/shadow, /etc/sudoers) before and after every scan to prove no tampering occurs.

⚠️ Authorized Use Policy

This toolkit is strictly intended for authorized security evaluations, defensive posture reviews, and academic demonstrations on systems where you possess explicit, written permission from the system owner.

Unauthorized scanning or privilege testing against third-party networks or systems violates computer security laws and professional codes of conduct. The authors assume no liability for unauthorized usage.

⚠️ Operational Limitations

  • Distribution Backports: Kernel CVE matching compares version strings. Enterprise distributions backport patches without incrementing the base version number; findings are advisory.
  • Limited Account Visibility: Unprivileged scans cannot read protected files (/etc/shadow). Such paths are explicitly reported as skipped.

Technology Stack

Zero runtime dependencies on production targets; standardized dev tooling.

Office Automation

Run It Yourself

Quick start instructions for running the toolkit on authorized Linux systems.

bash — quickstart 
# 1. Clone repository
git clone <repository-url>
cd linux-privesc-toolkit

# 2. Run a fast audit scan (pruning pseudo and remote filesystems)
python3 privesc_scan.py scan --fast --label audit_01

# 3. View generated reports
ls -la reports/
# reports/scan_audit_01.json
# reports/scan_audit_01.md
# reports/scan_audit_01.html

# 4. Compare before and after hardening
python3 privesc_scan.py compare reports/scan_before.json reports/scan_after.json
